00 · Informática desde cero

Las piezas básicas que vas a “atacar” más adelante: qué hay dentro de un ordenador, cómo guarda la información y cómo se comunican los programas.

1. ¿Qué es un ordenador por dentro?

🧠 Analogía: una cocinaLa CPU es el cocinero. La RAM es la encimera (rápida pero pequeña; al cerrar la cocina se limpia). El disco es la despensa (grande, lenta, todo se queda guardado). La tarjeta de red es el camarero que lleva y trae pedidos.
💡 ¿Por qué le importa a un pentester?Las contraseñas a veces están en RAM (Mimikatz las lee de ahí), los ficheros de configuración en disco guardan credenciales, y la red es por donde entramos.

3. Binario, hexadecimal y bytes

📘 DefiniciónEl ordenador solo entiende 0 y 1 (bits). 8 bits = 1 byte. Con un byte puedes contar de 0 a 255.

Esto es clave para las direcciones IP (cada número de una IP es un byte: por eso nunca pasa de 255).

Posición del bit1286432168421Total
192 =11000000128+64 = 192
10 =000010108+2 = 10
255 =11111111255
✍️ Ejemplo paso a paso: pasar 172 a binario ¿Cabe 128 en 172? Sí → 1 (queda 44). ¿64 en 44? No → 0. ¿32 en 44? Sí → 1 (queda 12). ¿16? No → 0. ¿8? Sí → 1 (queda 4). ¿4? Sí → 1 (queda 0). 2 → 0, 1 → 0.
Resultado: 10101100

Hexadecimal usa 16 símbolos (0-9 y A-F). Un byte = 2 dígitos hex: 255 = FF, 65 = 0x41 (la letra “A”). Lo verás en direcciones MAC (08:00:27:aa:bb:cc), en hashes y en exploits.

Base64 no es cifrado: es una forma de escribir datos binarios con letras. echo 'hola' | base64 → aG9sYQo=. Cualquiera puede decodificarlo.

⚠️ Codificar ≠ Cifrar ≠ Hashear Codificar (Base64, URL-encode): reversible por cualquiera, sin clave.
Cifrar (AES, RSA): reversible solo con la clave.
Hashear (MD5, SHA256, NTLM): huella de un solo sentido, no se “descifra”; se adivina probando.

4. Archivos, procesos y servicios

  • Archivo: datos guardados en disco con un nombre (ej. config.php).
  • Proceso: un programa en ejecución. Cada uno tiene un número (PID) y se ejecuta como un usuario. Si un proceso de root es vulnerable, quien lo explote obtiene permisos de root.
  • Servicio / demonio: proceso que se ejecuta en segundo plano esperando peticiones (servidor web, SSH, base de datos).
🧠 AnalogíaUn servicio es un dependiente detrás de un mostrador esperando clientes. El puerto es el número de ventanilla. Si el dependiente se deja engañar (vulnerabilidad), puedes hacer que te dé cosas que no debería, con su llave (sus permisos).

5. Cliente y servidor

Casi todo en Internet funciona así. Como pentester tú eres el cliente y buscas servidores que respondan cosas que no deberían.

6. Usuarios, permisos y el principio de mínimo privilegio

Cada usuario solo puede hacer ciertas cosas. Un ataque típico tiene dos saltos:

  1. Acceso inicial: entras como un usuario con pocos permisos (ej. www-data, el usuario del servidor web).
  2. Escalada de privilegios: aprovechas un error de configuración para convertirte en root/SYSTEM.

7. La tríada CIA y conceptos de seguridad

📘 Vulnerabilidad, amenaza, exploit, riesgo Vulnerabilidad: el fallo (una puerta mal cerrada).
Amenaza: quien podría aprovecharlo (un ladrón).
Exploit: la técnica/código que lo aprovecha (la ganzúa).
Payload: lo que haces una vez dentro (llevarte la tele).
Riesgo = probabilidad × impacto.
📘 CVE y CVSSCVE es el “DNI” de una vulnerabilidad pública (ej. CVE-2017-0144 = EternalBlue). CVSS es su nota de gravedad de 0 a 10. Lo usarás en el reporte.

📝 Evaluación del tema

✍️ Ejercicios

  1. Convierte a binario: 10, 172, 254.
  2. Decodifica este Base64 en tu Kali: cGFzc3dvcmQxMjM=
  3. Explica con una analogía propia la diferencia entre vulnerabilidad y exploit.
Ver soluciones

1. 10 = 00001010, 172 = 10101100, 254 = 11111110.

2. echo 'cGFzc3dvcmQxMjM=' | base64 -d → password123.

3. Ej.: vulnerabilidad = ventana del coche abierta; exploit = meter la mano por la ventana para abrir la puerta.

🧪 Práctica

Abre una terminal en Kali y ejecuta: whoami, id, uname -a, free -h, ps aux | head. Escribe en tus notas qué te dice cada comando (usuario, grupos, kernel, RAM y procesos).

Ver solución

whoami → tu usuario (kali). id → UID, GID y grupos (fíjate si estás en sudo). uname -a → versión del kernel (importante para exploits de kernel). free -h → memoria RAM. ps aux → procesos, con el usuario que ejecuta cada uno.
